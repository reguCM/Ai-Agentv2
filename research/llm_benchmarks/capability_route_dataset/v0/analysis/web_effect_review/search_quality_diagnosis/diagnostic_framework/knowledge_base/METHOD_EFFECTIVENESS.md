# METHOD_EFFECTIVENESS

各手法の「何に効く／何に効かない／いつ使う／信頼度」。  
評価ラベル: **採用** / **条件付き採用** / **有望** / **部分的に有効** / **未検証** / **不支持** / **単独では不十分**

---

## 全体仕様書（設計地図）

| | |
|--|--|
| 効果 | 経路の物語、意図レベルの前提共有 |
| 弱点 | 実装行帰属、stdout/LLM 混同の解消は保証しない。意図漏洩に注意 |
| 適用 | 入口説明・全体像が必要なとき。答えの行番号は書かない |
| 評価 | **部分的に有効** / 根拠行用途では **単独では不十分** |

---

## route decomposition

| | |
|--|--|
| 効果 | 表示経路と LLM 経路の接続テスト改善 |
| 弱点 | caller 誤認、原因過信、パック設計次第で ranking/filter 混同 |
| 適用 | handoff／表示が疑わしいとき。stdout と messages を別パックに |
| 評価 | **条件付き採用** |

---

## ranking / filter 分離パック

| | |
|--|--|
| 効果 | 段階の同一視抑制、score>0 の所属明確化 |
| 弱点 | return 後削減の過大評価など残差 |
| 適用 | 候補数変化・脱落理由が疑わしいとき |
| 評価 | **条件付き採用** |

---

## FACT / OBSERVED / INFERENCE / UNKNOWN

| | |
|--|--|
| 効果 | ログ未添付時の OBSERVED 捏造抑制 |
| 弱点 | 原因の正しさは保証しない。原因リスト埋め行動は残る |
| 適用 | **原則常時** |
| 評価 | **採用**（証拠ラベルとして） |

---

## N1（1接続ずつの Yes/No）

| | |
|--|--|
| 効果 | （仮説）誤接続率低下 |
| 弱点 | 未実験。コスト増の可能性 |
| 適用 | caller が複雑なとき（予定） |
| 評価 | **未検証** / **有望** |

---

## N2（経路存在ゲート）

| | |
|--|--|
| 効果 | 経路外モジュールを原因から落とす安全弁（設計意図） |
| 弱点 | 経路上の誤因果は通過。フル経路物語は過信を増やしうる |
| 適用 | 候補に「無いモジュール」語が含まれる／経路外疑い |
| 評価 | **条件付き採用**（存在フィルタ専用。原因強度には使わない） |

---

## N3（ログなし runtime 原因の禁止／UNKNOWN）

| | |
|--|--|
| 効果 | （仮説）存在 YES でも発生未観測なら原因断定しない |
| 弱点 | ログが粗いと真因も停止しうる |
| 適用 | runtime 症状診断、ログ無し時 |
| 評価 | **未検証** / **有望**（セレクタ候補） |

---

## 小型LLM（Qwen3:8b）

| | |
|--|--|
| 効果 | 入口発見、ログ列挙、長プロンプト処理（相対） |
| 弱点 | 経路接続、存在＝原因、根拠行ずれ |
| 適用 | 局所解析・一次候補生成 |
| 評価 | **条件付き採用**（局所）。全体最終診断の **単独では不十分** |

## DeepSeek-Coder-V2 16B

| | |
|--|--|
| 効果 | 短文接続で dumps を当てることがある |
| 弱点 | 長診断プロンプト不可、ログ照合弱、共通失敗残存 |
| 適用 | 短文 Yes/No の試行余地のみ |
| 評価 | **単独では不十分** / 全面置換 **不支持** |
